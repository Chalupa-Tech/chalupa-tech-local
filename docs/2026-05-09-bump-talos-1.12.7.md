# Bump Talos to v1.12.7

## Summary

Bump the declarative Talos version from `v1.12.6` (label) / `v1.12.0` (running) to `v1.12.7` in both `pulumi-talos/main.go` and `ansible/roles/proxmox_prep/defaults/main.yml`. Make the Talos ISO filename version-stamped so `proxmox_prep` actually re-downloads when the version changes.

The actual rolling OS upgrade of running nodes is a separate operational step (`talosctl upgrade` per node), tracked in the deploy notes for this change.

## Rationale

- Talos v1.12.0 ships an aggressive userspace OOM controller bug ([siderolabs/talos#12526](https://github.com/siderolabs/talos/issues/12526)) which we worked around in PR #151 (`OOMConfig: triggerExpression: "false"`). The upstream fix landed in v1.12.2; v1.12.7 is the latest 1.12.x patch and includes 5 additional kernel/containerd/etcd/Kubernetes patch updates.
- The on-disk OS version (`v1.12.0`) had drifted from the declarative label (`v1.12.6`). The Ansible ISO download task short-circuited on filename existence regardless of version, so bumping the version variable never re-downloaded. Versioning the filename closes that drift.
- The Pulumi VM CDROM `FileId` is wrapped in `IgnoreChanges([]string{"started", "cdrom"})`, so changing the filename does not touch existing VMs — only fresh provisioning picks up the new ISO.

## Changes

### `pulumi-talos/main.go`
- `talosVersion = "v1.12.7"` (was `v1.12.6`).
- VM `Cdrom.FileId` now interpolates the version: `local:iso/talos-nocloud-amd64-v1.12.7.iso`.

### `ansible/roles/proxmox_prep/defaults/main.yml`
- `proxmox_prep_talos_version: "v1.12.7"` (was `v1.12.6`).
- `proxmox_prep_talos_iso_name: "talos-nocloud-amd64-{{ proxmox_prep_talos_version }}.iso"` — version-stamped filename so subsequent bumps actually trigger the download. Comment explains why.

## Rollout

This PR is **declarative only** — merging it does not upgrade running nodes. The on-disk OS upgrade is a separate operational step run from a workstation with `talosctl`:

```bash
# Use the same factory schematic as the ISO so qemu-guest-agent extension is preserved
SCHEMATIC=ce4c980550dd2ab1b17bbf2b08801c7eb59418eafe8f279833297925d67c7515
IMAGE="factory.talos.dev/installer/${SCHEMATIC}:v1.12.7"

# Workers first, one at a time. --preserve keeps the STATE partition (PV data, etc.)
talosctl -n 192.168.1.232 upgrade --image "$IMAGE" --preserve   # worker-3
talosctl -n 192.168.1.227 upgrade --image "$IMAGE" --preserve   # worker-2
talosctl -n 192.168.1.226 upgrade --image "$IMAGE" --preserve   # worker-1

# Control planes sequentially — never two at once (etcd quorum)
talosctl -n 192.168.1.229 upgrade --image "$IMAGE" --preserve   # cp-3
talosctl -n 192.168.1.228 upgrade --image "$IMAGE" --preserve   # cp-2
talosctl -n 192.168.1.225 upgrade --image "$IMAGE" --preserve   # cp (etcd leader last)
```

Between steps: `kubectl get nodes` shows the node `Ready` and `Talos (v1.12.7)`. After all six: `talosctl etcd status` and `kubectl get pods -A` should be clean.

## Follow-up

Once on v1.12.7, the temporary `OOMConfig: triggerExpression: "false"` patch added in PR #151 can be removed (the upstream fix supersedes it). Tracked separately.
