# 2026-03-19: Fix Talos Machine Config Application (v5)

## Overview

Added `machine.NewConfigurationApply` resources to automatically apply Talos machine configurations to VMs after they boot into maintenance mode. Previously, configs were generated but never delivered to the VMs.

## Rationale

The Talos VMs boot from the `nocloud-amd64.iso` into maintenance mode and receive a DHCP IP. The machine configs (containing static IPs, DNS, etc.) were generated by `machine.GetConfiguration` but **never applied** to the running VMs. The `machine.NewBootstrap` then attempted to connect to the static IP (192.168.1.41) which the VM didn't have yet — causing bootstrap to fail.

The fix adds `machine.NewConfigurationApply` resources that:
1. Extract the VM's DHCP IP from the Proxmox QEMU guest agent output
2. Apply the Talos machine config (with static IPs) to each VM via its DHCP IP
3. After config application, VMs reboot with their static IPs
4. Bootstrap then targets the now-reachable static IP

## Changes

- **Pulumi (`talos.go`)**:
  - Added `extractVMIP()` helper to get the first non-loopback IPv4 from QEMU guest agent output
  - Added `machine.NewConfigurationApply` for the control plane VM
  - Added `machine.NewConfigurationApply` for each worker VM
  - Updated `machine.NewBootstrap` to depend on CP config apply (not just VM creation)
  - Added 15-minute timeouts for config apply and 10-minute timeout for bootstrap
  - Added `machine.BootstrapTimeoutsArgs` for bootstrap timeout
