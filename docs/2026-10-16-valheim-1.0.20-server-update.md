## Why

Valheim shipped 1.0.17 (2026-10-06) and 1.0.20 (2026-10-15). Valheim refuses
clients whose build does not match the server's, so once players' clients
auto-updated they could no longer join.

The server build is **not pinned**: `install.yml` runs DepotDownloader against
app `896660` with no manifest argument, so any Ansible run pulls whatever Steam
currently serves and the `Detect server update` task restarts the service when
the binary checksum changes. Nothing had to change in the repo to move the
build — what was missing was a *deploy*. The last Ansible run against the box
was 2026-09-15 (`57b13b2`); every `oracle-deploy` run since then finished in
~10s because `detect-changes` saw no `oracle-cloud-server/ansible/**` diff and
skipped the Ansible job entirely. So the host sat on a mid-September binary for
a month. This PR touches that path, which makes the deploy run as a side
effect of merging.

## Why the mods were bumped in the same change

Leaving the mods alone would have been the riskier option, not the safer one.
ServersideQoL 2.0.6's changelog entry is literally "Update for valheim 1.0.12",
and the mod ships a BepInEx **preloader patcher**
(`patchers/ServersideQoL.Patchers.dll`) built on Harmony transpilers — the
fragile kind of patch across game versions, and one whose failure can abort
startup rather than degrade quietly. Upstream has shipped eight releases since
2026-10-01, including a transpiler fix, and 2.3.3 landed on 2026-10-16, after
1.0.20. Running the current stable is the lower-risk position.

The Azumatt pins were only a few days stale against 1.0 when they were set, but
Hexium has carried five newer builds since; bumping them together keeps the
server and the documented client set in one coherent state.

Stable 2.3.3 was chosen over Hexium's `2.4.0-beta.1` (2026-10-13), which is a
beta and predates 1.0.20 anyway.

## Why AutoFeed had to go

Our `ServersideQoL_AutoFeed` 0.1.0
([repo](https://github.com/tayvenb13/serverside_qol-autofeed)) is a module
loaded by the ServersideQoL core and was built against core 2.0.6. It has no
newer release, so it would not load against 2.3.3 — and the SSQoL core bump is
the part of this change we least want to skip.

Upstream made the module redundant in the meantime: core 2.1.0's changelog
reads "Added support for TameAssist's new feeding from containers feature", and
`ServersideQoL_TameAssist` now exposes `FeedFromContainers`,
`FeedFromContainersRange`, `FeedFromContainersLeaveAtLeast` and per-chest range
overrides via ContainerSigns chest signs (`🐗64` on a sign widens that chest's
range) — a superset of what AutoFeed did. Adopting it means the feature is
maintained by someone who tracks Iron Gate's patches.

AutoFeed's zip contains no `patchers/` folder, so removing it leaves nothing
orphaned in `BepInEx/patchers`; `valheim_mods_absent` prunes its plugin
directory. Its stale `BepInEx/config/tayvenb13.ServersideQoL.AutoFeed.cfg` is
left on disk and is inert — the role has no mechanism for removing config
files, and adding one for a single dead file is not worth it.

## Pre-flight checks done before pinning

- All 16 download URLs (5 Hexium + 11 Thunderstore) return HTTP 200.
- All 13 new/changed mod zips carry `manifest.json` at the archive root, which
  is the `creates:` guard for the `Install mods into BepInEx plugins dir`
  unarchive task — so every one stays idempotent.
- The SSQoL patcher filename is unchanged between 2.0.6 and 2.3.3
  (`patchers/ServersideQoL.Patchers.dll`), so the `Install staged patcher DLLs
  into BepInEx/patchers` copy task overwrites the old patcher in place. That
  task only ever copies in, never prunes, so a renamed patcher would have left
  a stale DLL loading alongside the new one — worth re-checking on any future
  core bump.
- TameAssist's config section name is `TameAssist`, matching the
  `<ModName>` convention the existing `AutoStore` / `ContainerSigns` /
  `MultiplayerTweaks` entries already rely on (`ConfigBase.BindEx` binds to
  `Section` unless `UnifiedConfig` is on, which we do not set).

## Follow-ups

- `ServersideQoL_TameAssist` also offers `FedDurationMultiplier`,
  `TamingTimeMultiplier` and `MakeCommandable`, all left at vanilla-neutral
  defaults. `TeleportFollowers` / `TakeIntoDungeons` are popular QoL features
  and are one-line flips in `valheim_mod_settings` if wanted.
- The `serverside_qol-autofeed` repo is now unused. Archive it, or keep it as
  a reference for writing future SSQoL modules.
- The server build still is not recorded anywhere in the repo. If knowing
  which build is live matters, the options are pinning
  `-manifest`/`-beta` arguments in `install.yml` (deliberate, auditable
  updates, but then every Iron Gate patch needs a PR) or having the role write
  the installed build id to a file. Left as-is for now: unpinned matches how
  this box has been run, and the README now documents the consequence.
