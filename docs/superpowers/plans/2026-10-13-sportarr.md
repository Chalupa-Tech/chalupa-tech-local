# Sportarr Deployment Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deploy Sportarr (sports PVR) to the media stack with a Postgres backend on arrs-pg, a new `Sports/` library on the TrueNAS share, and scraparr metrics wiring — shipped as two PRs to avoid the ExternalSecret ordering wedge.

**Architecture:** A new ArgoCD-auto-discovered wrapper chart at `gitops/apps/media/sportarr/` (bjw-s app-template, mirroring radarr), plus Postgres role/database/secret wiring in the existing `arrs-pg` CNPG chart (single-DB seerr pattern, NOT radarr's main/log split), plus a scraparr connector stanza shipped as a **separate second PR** gated on the API key existing in OpenBao.

**Tech Stack:** Helm wrapper charts, bjw-s app-template 5.3.0, CloudNativePG `Cluster`/`Database` CRs, External Secrets Operator + OpenBao, Traefik IngressRoute, ArgoCD ApplicationSet auto-discovery.

**Spec:** `docs/superpowers/handoffs/2026-10-08-sportarr-handoff.md` (read it — it carries the approved design decisions and manual post-merge steps).

## Verified facts this plan relies on (re-checked 2026-10-13)

These update/confirm the handoff's open questions — do not re-litigate them,
but if an executor hits a contradiction (e.g. image tag gone), stop and
re-verify against the source listed:

- **Postgres: supported, single database, fresh installs only.** Sportarr is
  an EF Core rewrite, NOT Sonarr-v4 lineage. Env vars (exact spelling, from
  `src/Constants/ConfigurationKeys.cs` in Sportarr/Sportarr):
  `Sportarr__Database__Provider`, `__Host`, `__Port`, `__Name`, `__Username`,
  `__Password`. **No MainDb/LogDb split.** There is NO SQLite→Postgres
  migration path, so Postgres must be configured before first boot — which
  this plan does.
- **`/ping` exists**: `GET /ping` → 200 "pong", unauthenticated, on port
  1867 (Sportarr's own Dockerfile HEALTHCHECK uses it). Safe for probes.
- **Image tag**: `sportarr/sportarr:4.1.9.1119` on Docker Hub is what
  `latest` points at (digest-verified 2026-10-13, pushed 2026-09-27).
  Never pin `-dev` tags. Re-probe
  `https://hub.docker.com/v2/repositories/sportarr/sportarr/tags/?page_size=100`
  before pinning if executing later than ~2026-10.
- **Port 1867** confirmed (source + Dockerfile).
- **API v3**: Sportarr serves a frozen Sonarr-v3-contract shim at
  `/api/v3/*` (incl. `system/status`, `queue`, `calendar`, `wanted/missing`,
  `health`, `series`) — scraparr's `api_version: v3` sonarr-shaped scrape
  works against it.
- **app-template is 5.3.0**, not the handoff's 4.4.0 — Renovate bumped
  radarr's `Chart.yaml` since the handoff was written. Mirror 5.3.0.
- **No vmalert change needed** (handoff Part D): `vmalert/templates/rules/arrs.yaml`
  alerts generically on `scraparr_services_up` per `alias` label — no
  per-service enumeration exists. Sportarr is covered automatically.
- **No OpenBao policy change needed**: `scripts/openbao/policies/media-read.hcl`
  already grants read on `secret/data/postgres/*` and `secret/data/scraparr/*`.
- **No `wait-for-sportarr` init container**: scraparr chart 1.5.0's init
  regex is `radarr|sonarr|prowlarr|bazarr|readarr|lidarr|jellyseerr|overseerr$`
  — `sportarr` doesn't match (handoff Part C.4 resolved).
- **Vendored `charts/*.tgz` are gitignored** (`.gitignore`:
  `gitops/apps/*/*/charts/`). Commit `Chart.yaml` + `Chart.lock`, not the tgz.

**Deliberately skipped:** the handoff's optional Part C.5 (migrating the
seerr/overseerr-key workaround to a native `seerr:` connector stanza) — the
current `overseerr:` config works, the handoff marks it not required, and it
doesn't block anything here. Revisit separately if desired.

## Global Constraints

- All changes via PRs — never push to `main`; CI applies changes.
- No local `pulumi up` / `ansible-playbook` without `--check`; no `kubectl apply` — ArgoCD syncs from merged main.
- TrueNAS VM is protected — nothing in this plan touches it beyond NFS subPaths on the existing `media-plexmedia` PVC.
- Image: `sportarr/sportarr:4.1.9.1119` (Docker Hub, plain semver — Renovate will track it).
- Service/web port: `1867`; service name must be exactly `sportarr` (ingress + scraparr URL depend on it).
- Hostname: `sportarr.frame.chalupatech.com`; every IngressRoute MUST carry `external-dns.alpha.kubernetes.io/target: "192.168.1.230"` or external-dns silently skips it.
- Postgres host: `arrs-pg-rw.media.svc.cluster.local:5432`; DB name `sportarr`; secret `sportarr-pg` with keys `username`/`password`/`db` (seerr pattern).
- Document changes in `docs/` with rationale and PR links (critical rule).
- Local verification per task: `yamllint gitops/` + `helm dependency update <chart>` + `helm template <chart>` (+ `kubeconform` if installed) — same as the required "Lint and dry-render gitops/" CI check.

## PR strategy (ordering gotchas — read before executing)

- **PR 1** (`feat/sportarr`): Tasks 1–3. The sportarr app + arrs-pg wiring + docs + this plan.
  **Pre-merge manual gate:** OpenBao `postgres/sportarr` must be seeded BEFORE
  merging PR 1, or the `sportarr-pg` ExternalSecret fails to sync, the pod's
  `secretKeyRef` envs block startup, and the app wedges on first sync
  (ArgoCD selfHeal does NOT retry failed initial syncs; the appset retry
  config helps but don't rely on it).
- **PR 2** (`feat/sportarr-scraparr`, branched from origin/main — no file
  overlap with PR 1): Task 4. Opened as **DRAFT**; merged only after Sportarr
  is live and its real API key is seeded at OpenBao `scraparr/sportarr-api-key`
  (the `scraparr-apikeys` ExternalSecret has all keys mandatory — merging
  early wedges scraparr's deploy).
