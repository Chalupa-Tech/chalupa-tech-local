# Talos 1.14.1 upgrade + explicit Kubernetes version pin

**Date:** 2026-09-19
**PR:** [#345](https://github.com/Chalupa-Tech/chalupa-tech-local/pull/345)

## What happened

Renovate PR #275 bumped `talosVersion` v1.12.7 → v1.14.1 in
`pulumi-talos/main.go`. On merge, the deploy pipeline failed
([run 35241068708](https://github.com/Chalupa-Tech/chalupa-tech-local/actions/runs/35241068708)):

```
kubelet image is not valid: version of Kubernetes 1.36.0 is too new to be used with Talos 1.12.7
```

`talosVersion` drives machine-config *generation*, and when no Kubernetes
version is given, the generated config uses that Talos release's default
K8s (1.36.0 for Talos 1.14). The nodes were still running Talos 1.12.7 on
disk — a repo version bump does not upgrade the OS — and 1.12.7 rejects
K8s 1.36 images at apply time. The config was rejected at validation, so
the cluster was never at risk.

## Remediation (2026-09-17 → 2026-09-19)

Node OS upgrades are out-of-band from the pipeline, via `talosctl upgrade`
against each node with the factory installer image (same schematic as the
ISO, includes qemu-guest-agent), one minor version at a time:

1. 1.12.7 → 1.13.10 → 1.14.1, control-plane nodes first (one at a time,
   etcd quorum verified between nodes), then workers.
2. `talosctl --nodes 192.168.1.225 upgrade-k8s --to 1.36.0` after all
   nodes were on 1.14.1.
3. Re-ran the failed deploy workflow — config apply succeeds now that the
   nodes accept Talos 1.14 configs with K8s 1.36 images.

Operational gotchas hit along the way:

- **OpenBao PDB blocked a worker drain.** All three openbao replicas were
  unhealthy (sealed after earlier reboots; two stuck in `Completed`), so
  the PDB allowed zero disruptions. Fix: delete the dead pods (the
  StatefulSet is `OrderedReady`, so ordinal N only respawns after N-1 is
  ready), unseal each replica via `scripts/openbao/unseal.sh`, then
  resume. Expect to re-unseal the affected replica after every worker
  reboot.
- `talosctl upgrade-k8s` left kubelets half-rolled when the session
  driving it was interrupted; it is idempotent — re-running it finished
  the remaining nodes.

## Change in this PR

- Pin `kubernetesVersion` explicitly in `pulumi-talos/main.go` and pass it
  as `KubernetesVersion` in `machine.GetConfigurationOutput`, so a future
  `talosVersion` bump can no longer silently change the Kubernetes version
  the config asks for.
- Renovate now tracks the pin against `kubernetes/kubernetes` releases,
  gated behind dependency-dashboard approval (same as the Talos bump).

## Upgrade runbook going forward

1. **Talos:** upgrade nodes first (`talosctl upgrade`, one minor at a
   time, CPs then workers), *then* approve/merge the `talosVersion` bump.
2. **Kubernetes:** run `talosctl upgrade-k8s --to <ver>` first, *then*
   approve/merge the matching `kubernetesVersion` bump. Keep the version
   inside the running Talos release's support matrix.
